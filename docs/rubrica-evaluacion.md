# Rúbrica de Evaluación - Proyecto TaskFlow (Sprint 1)

Esta rúbrica se utilizará para evaluar el trabajo del equipo al final del Sprint.

| Criterio | Excelente (4 pts) | Bueno (3 pts) | Regular (2 pts) | Insuficiente (1 pt) | Puntos Obtenidos |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Funcionalidad** | Todas las historias de usuario del Sprint funcionan perfectamente y cumplen los criterios de aceptación. | La mayoría de las historias funcionan, pero hay 1 o 2 bugs menores. | Faltan funcionalidades clave o hay bugs que impiden el flujo normal. | La aplicación no funciona o no se entregó nada funcional. | |
| **Calidad del Código** | Código limpio, modular, bien nombrado y fácil de leer. Sigue principios SOLID. | Código legible, pero con alguna duplicación o malas prácticas menores. | Código difícil de leer, muy acoplado o con malas prácticas evidentes. | Código espagueti, sin estructura ni modularización. | |
| **Uso de Git/GitHub** | Uso impecable de ramas, commits semánticos, PRs revisados y tablero Kanban actualizado. | Uso correcto de Git, pero con commits poco descriptivos o PRs sin revisión exhaustiva. | Uso básico de Git (solo push a main), sin ramas ni PRs. | No se utilizó control de versiones o el repositorio está en caos. | |
| **Documentación y Proceso** | README completo, DoD respetada, y evidencia de ceremonias ágiles (dailys, retro). | Documentación básica presente, pero falta detalle en el proceso. | Documentación escasa o desactualizada. | Sin documentación. | |
| **Trabajo en Equipo** | Colaboración activa, todos participaron en el código y en las revisiones. | La mayoría participó, pero hubo desigualdad en la carga de trabajo. | Solo 1 o 2 personas hicieron todo el trabajo. | No hubo trabajo en equipo. | |
